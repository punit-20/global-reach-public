Privacy Policy

Effective Date: October 12, 2026 | Data Controller: Global Reach Team (punit-20)

Pre-Verification Status & Transparency Notice: Global Reach (Application ID: 722756633499009045) is currently in pre-verification preview and is not operating as an active public hosted service. Live cloud webhook listeners, in-Discord user opt-in/opt-out buttons, and interactive /campaign slash commands are not yet deployed. This Privacy Policy documents the exact Discord data categories, consent rules, retention limits, and deletion boundaries implemented in the Global Reach software.

1. Overview & Current Operational Scope

This Privacy Policy explains what information Global Reach (Application ID: 722756633499009045, "the Bot" or "the Service") processes and stores when interacting with the official Discord API, as well as the scope and limitations of data retention and user data removal.

  • Implemented Operator & Application Capabilities: Official Discord Bot identity verification, server registration, cryptographic interaction signature verification, individual user opt-in and opt-out management, administrator campaign approval verification, channel permission checks, single-dispatch announcement delivery, user data purge utilities, and expired audience snapshot cleanup.
  • Planned / Not Yet Deployed: Always-on cloud Gateway/webhook listeners, interactive in-Discord self-service opt-in/opt-out buttons, and /campaign slash commands.

2. Information We Collect & Process

When operated with authorized Discord servers, Global Reach processes only the following specific categories of Discord data:

Data Category Specific Fields Processed & Stored Purpose of Processing
Discord User Identifiers & Profile Metadata User ID, username, global/display name, server nickname, and automated bot account indicator. To verify user identity during consent or administrative interactions and to automatically exclude automated bot accounts from audiences.
Server (Guild), Role & Channel Metadata Registered Server ID, server name, server owner ID, role definitions, target channel ID, channel type, and channel permission overrides. To confirm server authorization, evaluate channel permission hierarchies, and ensure announcements are posted only in eligible server text or announcement channels.
Verified Consented Membership Attributes Server join timestamp, assigned role IDs, and verified individual consent metadata (interaction identifier, consent timestamp, and active/revoked status). To confirm that every non-bot holder of a target notification role has an active, unrevoked individual consent record prior to campaign dispatch.
Consent Registries, Administrator Approvals & Campaign Audit Logs Registered server IDs, configured opt-in role IDs, individual consent and global opt-out records, replay-protection interaction identifiers, approving administrator User ID, cryptographic campaign digest, approval lifecycle state, published Discord message ID, and delivery timestamp. To enforce opt-out precedence, prevent interaction replay, verify administrator approval integrity, prevent duplicate message dispatch, and maintain an operational audit trail.

What We Do Not Collect or Store: Global Reach does not read, monitor, or store user chat message contents, direct messages, file attachments, reactions, or voice activity.

3. Purposes of Processing & Strict Individual Consent Rules

  • Administrator-Assigned Roles Never Prove Consent: Holding a Discord server role assigned by an administrator is never treated as proof of individual user consent, and unverified caller-supplied identifiers are rejected. Each consent record requires a cryptographically verified, user-initiated Discord interaction matching the user's own account ID, server ID, and opt-in action, protected against replay.
  • Opt-Out Precedence & Fail-Closed Delivery Blocking: Global opt-outs take strict precedence over role membership and prior consent records. Campaign delivery is automatically blocked if consent is missing, revoked, or inconsistent, or if any non-bot member holding the target notification role lacks a verified individual consent record.
  • Verified Administrator Approval: Campaign approvals derive the acting administrator's identity strictly from a verified Discord interaction, confirm via the Discord API that the human user holds ADMINISTRATOR, MANAGE_GUILD, or Server Owner status, and cryptographically bind the approval to a SHA-256 digest of the campaign payload.
  • Single-Dispatch Channel Delivery: Approved announcements lock campaign state prior to delivery to prevent duplicate sends, target strictly server text or announcement channels with mentions restricted to the designated opt-in role, and require a confirmed message snowflake ID from Discord.

4. Data Storage, Retention & Deletion Boundaries

  • Isolated Storage: Operational consent registries, administrator approval records, campaign audit logs, and any temporary audience snapshots are stored in an isolated private operator environment using atomic file updates and are strictly excluded from public repositories.
  • Manual Operator Retention Controls (No Automatic Background Daemon): Data retention and snapshot cleanup utilities run when invoked by the operator (or via an operator-configured scheduler); the software does not run an autonomous background deletion daemon on its own. Temporary audience snapshots are subject to a 7-day retention policy via operator snapshot cleanup utilities.
  • What User Data Deletion Erases vs. Retains: Executing an operator user-deletion action for a Discord User ID atomically:
    1. Records a permanent global opt-out and replaces any server consent record for that user with a minimal revoked tombstone (retained specifically so role assignments cannot re-enroll the user),
    2. Revokes any pending campaign approvals created by that user ID, and
    3. Removes that user ID from temporary audience snapshots in the operator environment.
    Limitations of Erasure: Operator user deletion does not alter historical append-only campaign delivery audit entries (which record campaign metadata and approving administrator IDs rather than recipient member lists), does not modify external backups, and does not delete announcement messages already posted in Discord channels.

5. Third-Party Services & Data Sharing

  • Discord Inc.: When executed, the Service communicates directly with Discord's official API (discord.com).
  • GitHub Pages: This public documentation website is hosted statically on GitHub Pages. The website sets no tracking cookies, runs no third-party analytics scripts, and collects no form inputs.
  • No Sale or Brokerage: We do not sell, rent, license, or share Discord User IDs or community records with third-party advertisers or data brokers.

6. Security Practices

  • Official Discord Bot credentials are stored exclusively in private environment configurations, verified against Discord's official bot identity endpoint, and never logged or committed to public repositories.
  • All application logic, operational registries, and private workspaces are kept strictly separate from this public documentation site.

7. Privacy, Opt-Out & Data-Deletion Requests (Pre-Launch Status)

Global Reach is currently in pre-verification preview and is not operating as a live public hosted service.

  • Do Not Post Personal Identifiers Publicly: Never post your personal Discord User ID, Server ID, email address, or credentials in public GitHub Issues or GitHub Discussions.
  • Dedicated Private Privacy Intake Pending Pre-Launch Provisioning: A dedicated, monitored private intake channel for end-user privacy, opt-out, and data-deletion requests has not yet been provisioned while the project remains unhosted, and no automated response-time SLA is currently in effect. Before Global Reach is deployed to production or submitted for Discord verification, a dedicated private privacy contact route will be published in this section.
  • Server Administrator Assistance: Where an administrator or operator of a local Global Reach test instance receives a verified opt-out or deletion request inside their managed Discord community, the operator can immediately execute the built-in user opt-out and data-purge controls in their local environment.
