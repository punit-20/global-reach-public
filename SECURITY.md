# Security Policy

## Reporting a Security Vulnerability

**Do NOT report software security vulnerabilities or exposed credentials through public GitHub Issues or Discussions.**

Instead, please report security vulnerabilities privately through GitHub's built-in private vulnerability reporting channel:

1. **GitHub Private Vulnerability Reporting (Security Vulnerabilities Only):**
   Open a private security advisory at [https://github.com/punit-20/global-reach-public/security/advisories/new](https://github.com/punit-20/global-reach-public/security/advisories/new).
2. **Maintainer:**
   Global Reach Team (`punit-20`).

## Scope of This Channel

- **Security Vulnerabilities & Credential Leaks:** Include a concise description of the vulnerability, potential impact, and reproduction steps (redacting any live tokens or personal user data).
- **Privacy & Data-Deletion Requests:** GitHub Security Advisories is a vulnerability disclosure tool, not a general-purpose privacy request queue. Because Global Reach is currently in pre-verification preview, a dedicated monitored private privacy intake channel is pending pre-launch provisioning (see Section 4 and Section 7 of [`privacy.html`](./privacy.html)). Never post personal Discord User IDs or Server IDs in public GitHub Issues or Discussions.

## Credential Safety Reminder

If a Discord application token or account credential is ever accidentally exposed in logs, screenshots, or commits, immediately rotate the token in the [Discord Developer Portal](https://discord.com/developers/applications) (or reset the account password and enable 2FA) to invalidate the compromised credential.
